## お客様依頼フォームの設計思想（Phase57 以降）

- フォームは「部屋カルテ型」に寄せる：部屋ごとに工事内容・写真・希望が一体で見えること
- 初期表示はシンプル、詳細（状態・材料・写真）は折りたたみ内に格納。広さは常時表示（必須）
- クロスは「壁 / 天井 / 壁＋天井」として分離、床は「クッションフロア」として独立選択
- 「両方」という曖昧表示はお客様向けに廃止（内部 workType は互換維持）
- 動画は全体把握、写真は傷・詳細確認として役割を分ける
- 品番未定・情報未入力でも安心して送信できる設計を維持
- 将来的には roomMedia をDB正規化する（現状は meta JSONB に保存）

### 広さ・材料・アクセントの設計原則

- **広さは必須**：見積金額に直結するため必須化。ただし「不明」も許可し、離脱を防ぐ
- **材料希望（クロスのグレード）とアクセントクロスは別概念として分離**
  - 材料希望：量産 / 1000番・機能性 / まだ決まっていない（グレード・素材感）
  - アクセントクロス：一面だけ色/柄を変える・木目/石目調など（貼り方・演出）
  - 柄物はデザインの話、アクセントは配置の話 — 混在させない
- **状態に「穴」を追加**：クロス補修依頼で多い。「傷」と区別して職人が素早く判断できる
- **雰囲気カード（WALLPAPER_STYLES）は理想の空間イメージ**：アクセントとは別枠で選ぶ

### meta / 下書き保存の設計原則

- **wallWorkScope / floorWork が真の工事範囲**：`workType` は旧形式互換用としてのみ保持
  - `wallWorkScope`: `'wall' | 'ceiling' | 'wall_ceiling' | ''`
  - `floorWork`: `boolean`（クッションフロア ON/OFF）
  - 旧 `workType='両方'` は「壁クロス＋クッションフロア」の意味（天井なし）
- **localStorage draft には File/objectURL を保存しない**：復元時は `roomVideoFiles: [], roomImageFiles: []` で初期化
- **管理・職人側では requestMeta.ts の helper 経由で読む**：`getRoomWorkSummary()` が新旧両形式を処理
  - `hasCeilingWork()`: wallWorkScope / workType の両方をチェック
  - `getRoomWorkSummary()`: 「両方」は「クロス：壁 + 床：クッションフロア」に分解して表示
  - `getWallpaperAccentPreferences()`: `wallpaper_accent_preferences` を安全に取得
- **直接 `room.workType` を表示しない**：「両方」などの内部値が露出する

## 判断基準

新機能の優先度を決めるときは以下で判断する：

1. **実運用中の事故・トラブルを防ぐか？** → 最優先（S）
2. **職人の仕事が増えるか？** → S / A 優先
3. **職人が毎日開く理由になるか？** → A / B 優先
4. **依頼者のハードルが下がるか？** → A 優先
5. **DB 設計・法律・決済が絡むか？** → 慎重に C 以降
